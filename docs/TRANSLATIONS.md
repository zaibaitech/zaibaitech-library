# Adding a licensed translation

This is the workflow for adding a translation to a book, such as an English translation of Mukhtasar al-Akhdari. None may be added without a licence that covers the wording. The library's own English draft of al-Akhdari is registered but unpublished; see [its reviewer notes](translation-notes/akhdari-en.md).

The Arabic text's licence (OpenITI, CC BY-NC-SA 4.0) covers the Arabic only. It says nothing about a translation's rights. Every translation needs its own licence, and that licence must be compatible with how the site uses it, including non-commercial and share-alike terms if it is displayed alongside the CC BY-NC-SA Arabic.

## Where things live

| What | File | Notes |
| --- | --- | --- |
| Arabic text | `src/content/books/<book>.json` | Generated by `npm run content`. Never hand-edited. Regenerating it does not touch translations. |
| Translation metadata | `Book.translations` in `src/content/books.ts` | `TranslationInfo`: language, translator, source, licence, licence evidence, review status, review record. |
| Translation text | `src/content/translations/<book>/<translationId>.json` | `TranslationFile`: `passages` maps passage id → text. Registered in `src/content/translations/index.ts`. |

Passage ids are stable: `<chapterId>.<n>`, e.g. `wudu_faraid_sunan.2`. They are what bookmarks, saved positions and URLs use, and `npm test` fails if they drift. A translation attaches to the passage id, never to a position in a list, so reordering or a missing row cannot shift text onto the wrong Arabic.

## Steps

1. **Rights first.** Get written permission or a licence notice for the exact edition. Record where it is documented (`licenseEvidence`), e.g. a contract reference or the URL of the licence page. Do not start ingestion without this.

2. **Declare the translation, unpublished.** Add a `TranslationInfo` to the book with `reviewStatus: "unreviewed"`, the translator, source edition, licence, `licenseUrl` if any, and `licenseEvidence`. Pick a `translationId` that will not change, e.g. `en-<translator-surname>-<year>`.

3. **Export a worksheet.**
   ```bash
   npm run -s translations:worksheet akhdari > akhdari-worksheet.tsv
   ```
   One row per passage: `passage_id`, chapter, number, vowelled Arabic, an empty `translation` column, and `translator_note`. Give this to whoever aligns the translation. They fill the `translation` column only. A passage the edition does not translate stays empty.

4. **Import.**
   ```bash
   node scripts/translation-import.mjs akhdari-worksheet.tsv akhdari en-example-2027 en \
     > src/content/translations/akhdari/en-example-2027.json
   ```
   The import refuses unknown passage ids, duplicate rows, and rows whose Arabic no longer matches the book (a sign the sheet was sorted or edited). Empty rows are left out, so missing passages stay missing; they are never stored as empty strings.

5. **Register and validate.** Import the JSON in `src/content/translations/index.ts` and add it to `translationFiles`, then:
   ```bash
   npm run translations:check
   npm test
   ```
   **Errors** (block the change): undeclared `translationId`, book or language mismatch, unknown passage ids, empty strings, placeholder text (TODO, TBD, `[...]`), passages that are mostly Arabic script (source pasted by mistake), or a `"full"` review scope with untranslated passages.
   **Warnings** (for the reviewer): untranslated passages, passages out of book order in the file, and passages whose length is far off the median ratio to their Arabic, which usually means text slid onto a neighbouring passage.

6. **Review.** A qualified reviewer reads every translated passage beside its Arabic in the worksheet, and confirms the wording, the alignment, and that the Maliki context is kept. Use `reviewStatus: "in-review"` meanwhile. Readers see nothing at this stage.

7. **Publish.** Set `reviewStatus: "verified"` and add `review: { reviewer, reviewedOn: "YYYY-MM-DD", scope: "full" | "partial", notes }`. Only now does the reader offer the language. `isPublishable` (`src/lib/translations.ts`) refuses to show a translation unless it is verified, has a review record with a date, and has a translator, source, licence and licence evidence. The book page and reader show the translator, source and licence. Until then the text is not merely hidden: `publicContent` strips any unpublishable translation from what the reader page sends to the browser, so it cannot be read from the page source either.

8. **Incomplete translations.** A partial translation can be published with `scope: "partial"`. In "Arabic + translation" mode an untranslated passage says so. In "translation only" mode the Arabic is shown in its place, so the reader never loses text.

## What not to do

- Do not machine-translate and publish, even marked as a draft.
- Do not put translation text inside `src/content/books/*.json`. It is regenerated.
- Do not reuse a `translationId` for a different edition or translator.
- Do not edit the Arabic to make a translation fit. Arabic corrections go through `CORRECTIONS.md`.
